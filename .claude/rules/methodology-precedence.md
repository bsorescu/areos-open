# Methodology Precedence (conflict tiebreak)

When two loaded skills/rules give conflicting imperatives, do not resolve
ad-hoc. Apply, in order:

1. **Canonical chain order:** research (research-methodology) → brainstorm
   (superpowers:brainstorming) → plan (writing-plans) → implement (TDD) →
   review. A stage's gate fires before the next stage's gate; "before any
   creative work" imperatives queue behind an unmet research gate.
2. **Gates compose, they never cancel.** Two applicable gates = both run, in
   chain order. Skipping either requires the explicit user OK its own text
   demands.
3. **More specific mechanism wins** ties at the same stage (path-scoped rule
   over global; project over user; skill over generic instruction).
4. **Log every conflict encountered** as friction in the session note — each
   one is a candidate fix for this rule.
